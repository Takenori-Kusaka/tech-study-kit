# 03 ガイドのデッキ

## 構成の型（13 Part 前後）

0. 導入（なぜ今これが問題か、事故の例、全体の地図、読み方）
1〜10. 論点ごとの Part（各 Part は「扉 → 問い → 原則 → 製品ごとの違い → 失敗例 → 推奨 → まとめ」）
11. 運用・ガバナンス（台帳、変更の手順、レビュー、指標）
12. まとめ（最初の 90 日でやること、チェックリスト、参考文献）

各 Part の扉で「この Part の問い」と「結論」を先に言う。パンくず（STAGES）で全体のどこにいるかを示す。

## スライドの約束

- 1 枚 1 メッセージ。タイトルは結論の文にする
- 根拠の行 `refs: { spec, inst, book }` を全スライドに置く（デッキの生成器の `L.refs`）。book は『書名』章・節 p.xx
- 発表者ノートに、スライドに書けなかった説明と但し書きを書く（読むだけで発表できる量）
- 製品名・仕様名・数値には日付と版を添える
- 用語は初出で説明する。表記はファイル冒頭の用語表で揃える

## 作り方

リポジトリの立ち上げは [01 の「新しいリポジトリを立ち上げる」](01-scoping.md#新しいリポジトリを立ち上げる)。

```bash
cd E:/Github/<slug>-guide/deck && npm ci           # 初回だけ
bash make.sh                                        # pptx → 検証 → QA（PNG・はみ出し・重なり）
powershell -File export.ps1                         # PDF と 2560×1440 の PNG
python ../tools/build_web_slides.py ...             # docs/ に Web 版
```

- Part ごとにサブエージェントに書かせてよい。ただし **lib.js のヘルパーだけを使う**、**refs を必ず書く**、**1 枚の文字数の上限**を指示する
- QA の出力（`qa/overflow.txt`、重なりの検出、グリッド画像）を必ず見る。サブエージェントが書いたスライドは表と注記の重なり、はみ出しが多い
- 低解像度の PNG ではアンダースコアが消えて見える。判断は 2560×1440 で

## 完成の条件

- `qa/overflow.txt` が空、重なりの検出が 0
- 全スライドに refs と発表者ノートがある
- ファクトチェック（[04](04-factcheck.md)）の指摘をすべて反映
- PDF・Web 版を目で見て崩れがない
